# Phase 34: CodeGen File Splitting - Implementation Plan

## Current State Analysis

### Problems with Current CodeGen
1. **Single monolithic file** - All entities in one file (10,000+ lines for large DBs)
2. **Poor IDE performance** - Large files slow down IntelliSense
3. **Merge conflicts** - Multiple developers editing same file
4. **Hard to navigate** - Finding specific entity is difficult
5. **No partial class support** - Can't extend entities easily

### Current Output
```
MyDb.cs (10,000+ lines)
├── MyDbContext class
├── User class
├── Order class
├── Product class
└── ... (100+ entities)
```

## Target Architecture

### New Output Structure
```
Models/
├── Context/
│   └── MyDbContext.cs          (DataContext only, ~50 lines)
├── Entities/
│   ├── User.cs                 (One entity, ~30 lines)
│   ├── Order.cs                (One entity, ~40 lines)
│   ├── Product.cs              (One entity, ~35 lines)
│   └── ... (one file per table)
└── _Generated.cs               (Shared using statements, optional)
```

### Benefits
1. ✅ **Better IDE Performance** - Small files load instantly
2. ✅ **Easy Navigation** - Ctrl+T to jump to entity
3. ✅ **Better Git Diffs** - Only changed entities show up
4. ✅ **Fewer Merge Conflicts** - Team works on different files
5. ✅ **Partial Classes** - Easy to extend in separate files
6. ✅ **Code Review** - Review one entity at a time

## Implementation Strategy

### Phase 1: Refactor CodeGenerator (No Breaking Changes)

**Step 1: Extract Generation Methods**
```csharp
public static class CodeGenerator
{
    // Existing method - keep for backward compatibility
    public static string Generate(DbmlModel model, string targetNamespace)
    {
        // Calls new methods internally
    }
    
    // New methods for split generation
    public static string GenerateContext(DbmlModel model, string targetNamespace)
    public static string GenerateEntity(DbmlTable table, string targetNamespace)
    public static string GenerateFileHeader(string databaseName)
}
```

**Step 2: Add FileGenerationMode Enum**
```csharp
public enum FileGenerationMode
{
    SingleFile,    // Legacy mode - all in one file
    SplitFiles     // New mode - one file per entity
}
```

**Step 3: Add GenerateFiles Method**
```csharp
public static Dictionary<string, string> GenerateFiles(
    DbmlModel model, 
    string targetNamespace,
    FileGenerationMode mode = FileGenerationMode.SplitFiles)
{
    var files = new Dictionary<string, string>();
    
    if (mode == FileGenerationMode.SingleFile)
    {
        // Legacy mode
        files[$"{model.ContextClassName}.cs"] = Generate(model, targetNamespace);
    }
    else
    {
        // Split mode
        files[$"Context/{model.ContextClassName}.cs"] = GenerateContext(model, targetNamespace);
        
        foreach (var table in model.Tables)
        {
            files[$"Entities/{table.TypeName}.cs"] = GenerateEntity(table, targetNamespace);
        }
    }
    
    return files;
}
```

### Phase 2: Update CLI Tool

**Add Command Line Options**
```csharp
[Option("split", Default = true, HelpText = "Generate one file per entity (default)")]
public bool Split { get; set; }

[Option("single-file", HelpText = "Generate single monolithic file (legacy)")]
public bool SingleFile { get; set; }

[Option("output-dir", Required = false, HelpText = "Output directory for split files")]
public string OutputDirectory { get; set; }
```

**Update Main Logic**
```csharp
var mode = options.SingleFile 
    ? FileGenerationMode.SingleFile 
    : FileGenerationMode.SplitFiles;

var files = CodeGenerator.GenerateFiles(model, options.Namespace, mode);

if (mode == FileGenerationMode.SingleFile)
{
    // Write to single file
    File.WriteAllText(options.Output, files.First().Value);
}
else
{
    // Write to multiple files
    foreach (var (path, content) in files)
    {
        var fullPath = Path.Combine(options.OutputDirectory, path);
        Directory.CreateDirectory(Path.GetDirectoryName(fullPath));
        File.WriteAllText(fullPath, content);
    }
}
```

### Phase 3: Optimize Generated Code

**Optimization 1: Remove Redundant Using Statements**
```csharp
// Before (in every file)
using System;
using System.Data;
using LiteSql;
using LiteSql.Mapping;

// After (only what's needed)
// Context file
using System.Data;
using LiteSql;

// Entity file
using LiteSql.Mapping;
```

**Optimization 2: Shorter File Headers**
```csharp
// Before (verbose)
// <auto-generated>
//   Generated by LiteSql.CodeGen from DBML
//   Database: MyDatabase
//   Date: 2026-04-02 14:24:06
//   Changes to this file may be overwritten.
// </auto-generated>

// After (concise)
// <auto-generated />
// Generated by LiteSql.CodeGen - Do not modify
```

**Optimization 3: Partial Classes by Default**
```csharp
// All generated classes are partial
public partial class MyDbContext : LiteContext { }
public partial class User { }
public partial class Order { }
```

**Optimization 4: Namespace File Scoped (C# 10+)**
```csharp
// Before
namespace MyApp.Models
{
    public partial class User
    {
        // ...
    }
}

// After (C# 10+)
namespace MyApp.Models;

public partial class User
{
    // ...
}
```

## Migration Guide

### For Existing Users

**Option 1: Keep Single File (No Changes)**
```bash
# Add --single-file flag
litesql-codegen -c "..." -n MyApp.Models -o MyDb.cs --single-file
```

**Option 2: Migrate to Split Files**
```bash
# Step 1: Generate to new directory
litesql-codegen -c "..." -n MyApp.Models -o Models/ --split

# Step 2: Update project file
<Compile Include="Models\Context\*.cs" />
<Compile Include="Models\Entities\*.cs" />

# Step 3: Delete old single file
rm MyDb.cs
```
